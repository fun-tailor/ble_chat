# 01 · 包、import 路径与 pywinrt 的写法

## 1. pip 包名 → import 路径

pywinrt（Python/WinRT）v3 用 **`winrt-Windows.<Namespace>`** 作为 pip 名，import 时把点全换成下划线小写：

| pip 包 | import |
| --- | --- |
| `winrt-Windows.Foundation` | `winrt.windows.foundation` |
| `winrt-Windows.Foundation.Collections` | `winrt.windows.foundation.collections` |
| `winrt-Windows.Storage.Streams` | `winrt.windows.storage.streams` |
| `winrt-Windows.Devices.Bluetooth` | `winrt.windows.devices.bluetooth` |
| `winrt-Windows.Devices.Bluetooth.GenericAttributeProfile` | `winrt.windows.devices.bluetooth.genericattributeprofile` |
| `winrt-Windows.Devices.Enumeration` | `winrt.windows.devices.enumeration` |
| `winrt-Windows.Devices.Radios` | `winrt.windows.devices.radios` |
| `winrt-Windows.Devices.Bluetooth.Advertisement` | `winrt.windows.devices.bluetooth.advertisement` |
| （运行时核心）`winrt-runtime` | `winrt.runtime` / `winrt.system` |

### 1.1 谁真正需要被钉住？

`bleak` 自己在 Windows 上就声明了这些依赖（`bleak` 的 metadata）：

```
winrt-runtime>=3.1
winrt-windows-devices-bluetooth>=3.1
winrt-windows-devices-bluetooth-advertisement>=3.1
winrt-windows-devices-bluetooth-genericattributeprofile>=3.1
winrt-windows-devices-enumeration>=3.1
winrt-windows-devices-radios>=3.1
winrt-windows-foundation>=3.1
winrt-windows-foundation-collections>=3.1
winrt-windows-storage-streams>=3.1
```

所以 `requirements.txt:7-14` 里列出的 6 个包是**本项目自己直接 import 的子集**，
`Advertisement` / `Radios` / `winrt-runtime` 是 bleak 拉进来的（仍建议一起钉版本，
否则 bleak 升级会连带把绑定抬上去）。注意 pip 包名里既有 `winrt-Windows.*` 也有 `winrt-runtime`，
**不要写成 `winrt==`**（没有这个包）。

### 1.2 包内部结构

```
site-packages/winrt/
  _winrt.cp311-win_amd64.pyd                     # 核心
  _winrt_windows_devices_bluetooth*.pyd / .pyi   # 每个 namespace 一个原生扩展 + 类型存根
  runtime/   system/   windows/
  windows/devices/bluetooth/genericattributeprofile/__init__.py   # 手写的薄壳
```

`windows/**/__init__.py` 是**生成的薄壳**（第一行 `# WARNING: Please don't edit this file.
It was generated by Python/WinRT v3.2.1`），只做两件事：
从原生扩展 re-export 类 + 用纯 Python 定义 `enum.IntEnum` / `enum.IntFlag`。
所以**枚举可以在 Python 里读源码**（例如 `genericattributeprofile/__init__.py:96-158`），
而**类本身没有 Python 实现**（属性/方法在 `.pyd` 里，只能靠 `.pyi` 存根看）。

> 存根位置：`site-packages/winrt/_winrt_<namespace>.pyi`。
> 例如 `GattSessionStatusChangedEventArgs` 定义在
> `_winrt_windows_devices_bluetooth_genericattributeprofile.pyi:1126`。

## 2. 静态方法在**元类**上 —— `dir()` 会骗你

pywinrt 把 WinRT 的静态工厂方法放在 `type(SomeClass)`（一个叫
`GattServiceProvider_Static` 的元类）上，`dir(类)` **不包含**它们，但 `hasattr` 能拿到：

```python
>>> from winrt.windows.devices.bluetooth.genericattributeprofile import GattServiceProvider as SP
>>> 'create_async' in dir(SP)
False
>>> hasattr(SP, 'create_async')
True
>>> [n for n in dir(type(SP)) if not n.startswith('_')]
['create_async', 'mro']
>>> type(SP).__name__
'GattServiceProvider_Static'
```

**推论：想知道一个 WinRT 类有哪些静态方法，用 `dir(type(X))`，不要只 `dir(X)`。**

同理适用于：

| 类 | 静态方法（在元类上） | 实例上 `dir()` 能看到吗 |
| --- | --- | --- |
| `GattServiceProvider` | `create_async` | 否 |
| `DataReader` | `from_buffer` | 否（`dir(DataReader)` 无 `from_buffer`） |
| `GattDeviceService` | `from_id_async`、`get_device_selector_*` | 否 |
| `BluetoothAdapter` | `get_default_async`、`get_device_selector` | 否 |
| `BluetoothDeviceId` | `from_id` | 否 |
| `GattLocalService` | —（全是实例方法 `create_characteristic_async`） | 是 |

本项目用到的静态调用：

- `GattServiceProvider.create_async(UUID_SERVICE)` — `blechat/ble/server.py:195`
- `DataReader.from_buffer(buf)` — `blechat/ble/server.py:95`
- `BluetoothAdapter.get_default_async()` — `blechat/ble/server.py:477`

## 3. 枚举：`IntEnum`/`IntFlag`，`int()` 直接可用

生成的枚举是标准 Python `enum`：

```python
from winrt.windows.devices.bluetooth.genericattributeprofile import (
    GattCharacteristicProperties as Props,
    GattServiceProviderAdvertisementStatus as AdvStatus,
    GattSessionStatus,
)

int(GattSessionStatus.CLOSED)      # 0
int(GattSessionStatus.ACTIVE)      # 1
Props.WRITE | Props.WRITE_WITHOUT_RESPONSE   # IntFlag 位或直接可用
AdvStatus(self._provider.advertisement_status).name   # 已是枚举也能再包一层
```

## 4. COM apartment（本项目没有显式管，但要知道）

`winrt.runtime` 提供：

```python
from winrt.runtime import ApartmentType, init_apartment, uninit_apartment
ApartmentType.MULTI_THREADED  # = 0 (MTA)
ApartmentType.SINGLE_THREADED # = 2 (STA)
init_apartment(ApartmentType.MULTI_THREADED)
```

实测：**不显式调用也能直接用 WinRT 对象**（`DataWriter()` 在主线程直接可用），
因为 pywinrt 在首次使用时会自动初始化。本项目 `blechat/` 全库
`grep init_apartment` 无命中 —— 属于"让默认行为生效"的有意省略。

为什么值得记：**WinRT 事件回调来自线程池（MTA）**，与 asyncio 主线程不是同一个线程，
这直接决定了 `03-async-events-threads.md` 里的线程模型。

```python
# blechat/ble/server.py:11-20  ← 全项目唯一直接 import winrt 的文件
from winrt.windows.devices.bluetooth.genericattributeprofile import (
    GattCharacteristicProperties as Props,
    GattLocalCharacteristic,
    GattLocalCharacteristicParameters,
    GattProtectionLevel,
    GattServiceProvider,
    GattServiceProviderAdvertisementStatus,
    GattServiceProviderAdvertisingParameters,
)
from winrt.windows.storage.streams import DataReader, DataWriter
# blechat/ble/server.py:475（函数内延迟 import）
from winrt.windows.devices.bluetooth import BluetoothAdapter
```

其余地方**不碰 winrt**：客户端走 bleak（见 `08-client-via-bleak.md`），
UI/协议/持久化层与 Windows 无关（DPAPI、注册表另见 `09-win32-interop.md`）。
